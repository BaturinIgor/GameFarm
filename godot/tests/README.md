# Автотесты

Проверяют правила игры без мира и интерфейса: уровни и опыт, рюкзак и склад, продажу, таланты, мастерскую,
энергию, зверей и добычу без игры, усадьбу, задания, сохранение, таблицы данных и переводы на все языки.

## Запуск

```sh
sh tools/godot_sync.sh                      # строки и карты из iOS-проекта (один раз)
godot --headless --path godot --import      # один раз после клонирования
godot --headless --path godot -- --run-tests            # все тесты
godot --headless --path godot -- --run-tests energy     # только где в имени файла или теста есть "energy"
```

Код выхода 1, если хоть один тест упал. Сохранение тестов пишется в `user://test_save.json` и удаляется после
прогона, настоящий прогресс не трогается.

В CI тесты идут в `.github/workflows/tests.yml` на каждый push и PR, а в сборках APK и IPA - шагом перед экспортом.
Папка `tests/` в сборку не попадает (`exclude_filter` в `export_presets.cfg`).

## Как написать тест

Файл `tests/test_<что проверяем>.gd`, каждая функция `test_*` - отдельный тест:

```gdscript
extends "res://tests/test_case.gd"


func test_sell_more_than_have() -> void:
	Game.save["storage"]["wood"] = 3
	eq(Game.sell("wood", 1000), 3 * Game.sell_price("wood"), "продаётся только то, что есть")
	eq(Game.storage_of("wood"), 0)
```

- Перед каждым тестом раннер делает `fresh()`: новое сохранение, как у нового игрока. Своё начало -
  `fresh({"level": 20, "coins": 5000})` или `set_level(n)`.
- Проверки: `check(cond, msg)`, `eq(actual, expected, msg)`, `near(a, b, eps, msg)`, `between(v, lo, hi, msg)`.
  В отчёте видно сообщение и строку теста.
- Ошибка скрипта во время теста (обращение к несуществующему ключу, вызов на null) роняет тест.
  Если тест специально кормит игру плохими данными и ждёт ошибку движка (например, испорченный JSON),
  в начале вызови `expect_engine_errors()`.
- Случайность: перед каждым тестом `seed()` от имени теста, результат повторяется от прогона к прогону.

Правило: новая механика или исправленный баг - вместе с тестом.

## Боты-игроки

`tests/sim/bot.gd` играет сессиями по настоящим правилам (системы `Game`) в ускоренном времени: `Clock.offset`
сдвигает часы правил, поэтому энергия, стройка, цеха и звери без игры считаются как у живого игрока.
Мир заменён моделью: точки добычи из раскладок карт, удары по прочности, расход энергии, восстановление точек.
Бои, подземелья, ивенты, огород и мини-игры бот не трогает.

```sh
godot --headless --path godot -- --simulate                # все профили, 60 дней
godot --headless --path godot -- --simulate active 120     # один профиль, 120 дней
```

Профили в `tests/sim/sim_runner.gd`: `casual` (3 захода по 15 минут), `active` (6 по 20), `noads` (без роликов),
`payer` (стартовый набор, Pro, строитель, MAX, кристаллы), `whale`. Отчёт - `user://sim/<профиль>.json`:
уровни по дням и часам игры, усадьба, инструменты, монеты, на каком товаре ждала стройка, что продавалось.
На GitHub: Actions -> Bots -> Run workflow, отчёты в артефактах.

Все правила игры берут время из `Clock.now()`, а не из `Time.get_unix_time_from_system()`, иначе боты их не видят.
